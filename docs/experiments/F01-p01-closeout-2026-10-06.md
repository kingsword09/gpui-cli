## 大输入原实现基线复跑（2026-10-08）

在干净 `8effdf9` 上使用既有 `large_project_input_index_benchmark`，通过稳定 full-content
oracle 取得 F01 的原实现基线；该命令也保留 T05 indexed path 的配对数据。完整 raw JSON 位于
ignored `artifacts/acceptance/8effdf9/F01/macos-arm64/attempt-11/large-input-release-benchmark.json`，
SHA-256 `346f28ad319a1fa4b3453995b0523b52480d1820681c1f69ebfa865127d03c23`。

环境为 Apple M2 / macOS 15.6.1 / arm64 / Rust 1.97.1 release，warm filesystem cache，
不清空全局 page cache。数据集 4096 个 8192-byte 文件（32 MiB），每组修改一个文件并恢复
原大小和 mtime；按交替顺序执行 10 warmup + 30 measured pairs。Full-scan oracle P50/P95
为 167.20/171.18 ms，process CPU P50/P95 为 166.72/169.65 ms；index 配对 P50/P95 为
1.39/2.58 ms。每次 oracle 两轮稳定扫描，共 hash 8192 个文件/64 MiB；30 组均
`oracle_equal=true`，`wrong_revision_acceptance=0`。

这些数字只描述一台机器上的合成、热缓存、单文件变更场景。它们补充 F01 的 full-scan
baseline，不代表跨平台性能，不关闭 T05/T06 各自责任，也不等于完整 P-02 通过。
