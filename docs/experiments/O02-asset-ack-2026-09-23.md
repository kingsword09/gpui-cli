# O02：资源 received/cache-invalidation ACK（2026-09-23）

状态：in_progress。本子 PR 将资源热更新从“广播已发送”推进到带
`asset_revision` 的 runtime ACK：app 在 UI 线程完成缓存失效后回传成功/失败路径，
supervisor 只接受当前 desired revision 的 ACK。

## 实现

- `asset_changed` / `asset_data` 携带 `asset_revision`；
- runtime 将资源事件按 revision 聚合，在 GPUI foreground context 驱逐 Embedded/Path
  缓存后发送 `assets_applied`；写入失败、base64 失败会进入 failed 路径；
- supervisor 写入 `assets.applied` 事件，并更新 `RunState.assets_confirmed`；旧 revision
  或失败路径不能把当前资源标为已确认；
- `gpui-dev-protocol` 增加 `AssetsApplied` DTO，保持 1 MiB 帧上限和有界 ACK 路径；
- 现有 `AssetsSent` 仍表示传输动作，`AssetsApplied` 才表示 runtime 已完成缓存失效。

## 边界

ACK 不证明图片已经被 GPU 呈现，也不证明场景使用了新资源；scene/frame 证据属于后续
观察与 capture 阶段。删除资源事务和 manifest/hash 对账仍待后续 O02 子 PR。
