# S04：check 核心状态机与断言报告（2026-09-28）

状态：`in_progress`。本切片先固定 check 执行器与真实 runtime 之间的边界；它不启动 GPUI
进程、不模拟 macOS 窗口，也不把 fake runner 单测当成真实平台验收。

## 已实现

- `CheckPlan` 从已解析的 schema-v1 场景复制有限步骤和总 deadline，拒绝空场景、空身份或
  零 timeout；平台 runner 必须在传入的 `Instant` deadline 前返回。
- `ScenarioRunner` 注入 prepare/observe/action/wait/capture/cleanup。核心按
  prepare → step → cleanup 顺序执行，动作成功后必须重新 observation；`wait_for` 不使用
  固定 sleep 推断 ready。
- `CheckReport` 保存 scenario/component/fixture hash、最终状态、每步耗时、前后 observation
  id、log seq、输入 operation、断言实际值和 capture artifact 引用。
- 语义断言区分“semantics 不可用”（`inconclusive`）与“空树中没有节点”（`absent` 可通过）；
  unknown enabled/focused/visible/clip、缺 runtime errors、不可比 screenshot 都不会通过。
- action `unknown`/取消、driver unavailable/timeout 和断言失败都有明确终态；终止步骤后的
  依赖步骤记录为 `skipped`。动作已送达但后续 observation unknown 时仍保留 operation id。
- cleanup 总是尝试并单独记录；只有主流程原本通过时 cleanup failure 才将最终状态改为
  `failed`，不会覆盖已有的 `failed`/`inconclusive`/`unavailable` 主错误。
