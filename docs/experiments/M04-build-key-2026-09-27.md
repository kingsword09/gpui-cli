# M04：BuildKey 维度与稳定摘要切片（2026-09-27）

状态：`in_progress`。本切片只定义并测试 BuildKey 的完整维度、规范化和内容摘要，
不接入构建缓存、并发合并或输出目录隔离。

## 行为

- `BuildKeyMaterial` 显式包含 source manifest、Cargo.lock、target triple、profile、
  features、ABI、native config、toolchain、允许的环境摘要和 preview registry 摘要；
- `BuildKey::new` 拒绝缺失的必需维度，规范化 feature 名称的空白、排序和重复项；
- 规范化后的结构使用固定 JSON 字段顺序计算 SHA-256 `key_hash`，序列化结果同时保留
  material 和摘要，便于输出 `E/build-keys.json` 类证据；
- 环境变量、toolchain 和 native 配置的具体收集/筛选仍由后续调用方负责，本类型不自动
  扫描环境，也不把秘密值放入 key。

## 验证

- 重复或不同顺序的 features 得到相同 key；
- source、lock、target、profile、features、ABI、native、toolchain、environment 和
  preview registry 任一维度变化都会改变摘要；
- 空必需维度、空 feature 和空 ABI 明确拒绝；
- 序列化证据同时包含规范化 material 与 64 位十六进制摘要。

## 未覆盖

本切片没有构建执行器、缓存命中、同 key 在途任务合并、Android JNI/iOS DerivedData
staging 隔离，也没有自动计算 toolchain/native/env hash。完整 M04 仍须把 Cargo scope
纳入冻结副本，完成 path dependency relocation 和独立输出目录。
