## 实验 adapter

仅在临时项目增加 adapter：

- `crates/app/Cargo.toml`：加入 `serde_json`，并增加
  `p01-test-support = ["gpui/test-support"]`。
- `crates/desktop/Cargo.toml`：转发同名 feature。
- `crates/app/src/lib.rs`：注册 30 次 `Window::on_next_frame`，每次记录
  `bounds`、`scale_factor`、`debug_a11y_tree_json()`、`is_a11y_active()` 和
  monotonic hook 时间；test-support 下调用 `render_to_image()`。
- `crates/desktop/src/main.rs`：窗口创建后注册 adapter。
- UI 阻塞实验额外支持 `P01_BLOCK_UI_FRAME` 和 `P01_BLOCK_UI_MS`，只对临时
  项目生效。

没有改动本仓库生产代码，也没有把补丁放入 Cargo 缓存。

## 结果

### 普通 feature

- 编译成功，30 个 JSON probe，frame 为 `0..29`。
- `bounds` 始终为 origin `(192, 25)`、size `1536×1055`；`scale_factor` 始终为
  `1.0`。
- `captured_at_ms` 从 `16.571708` 到 `586.839375`，按文件序递增。
- `a11y_active=false`，`a11y_tree=null`。
- `scene_readback="not_compiled"`。
- `presented_frame="not_proven"`。
- `cx.quit()` 在第 30 个 probe 后执行，进程自然退出。
- 30 个 JSON 共 8,921 bytes；按 `shasum -a 256 probe-*.json | shasum -a 256`
  生成的 manifest hash 为
  `8c345040182bc0fddeeb482ba4dc42c9a7ec3d17d489fb97c061da7fb4b75e77`。

### `test-support` feature

- 编译成功，30 个 JSON probe，frame 为 `0..29`，窗口 bounds/scale 与普通版一致。
- 每次 `Window::render_to_image()` 都返回：
  `render_to_image not implemented for this platform`。
- 因此没有 PNG scene readback 产物；不是“捕获成功但未保存”。
- `a11y_active=false`、`a11y_tree=null`，`presented_frame` 仍为
  `not_proven`。
- 30 个 JSON 共 11,270 bytes；manifest hash 为
  `91958a9faba60c2d28b734485bc11c37e4bb917a959f436833fad292dfa979f5`。
- target 目录大小：普通版 4,441,256 KiB；test-support 版 4,661,216 KiB。
  该差异包含 feature 新增测试依赖和独立 target 缓存，不作为运行时开销结论。

### UI 线程阻塞与生命周期

5 秒阻塞实验生成 30 个 JSON 并自然退出。frame 5 的 hook 在
`145.004750 ms` 进入，`5145.288791 ms` 才完成；frame 6 在
`5148.228791 ms` 恢复。该实验直接证明 UI 线程被阻塞时本 adapter 不会产生
中间 hook，恢复后仍可继续排队并到达 frame 29。

15 秒阻塞的 screenshot 运行同样在 frame 29 自然退出；frame 5 的
`ui_blocked_ms=15000`，最后一帧时间为 `15512.227583 ms`。

本实验是直接 `cargo run` 的独立窗口，没有接入 `gpui run --live` transport，
所以没有证明“transport 在 UI 阻塞期间保持活动”。没有执行窗口手动关闭、系统
休眠/恢复或 device-loss 注入；这些项保持 `not_run`。

### a11y

在未启动屏幕阅读器/辅助技术的正常桌面会话中，API 可调用但返回 inactive/null。
本次没有得到可供校验的 role、value、clip、logical ID 或树分页数据；因此不能
把临时 a11y 节点别名当成稳定 logical ID，也不能声称无需激活即可导出语义树。

### OS window screenshot

`CGWindowList` 枚举到目标窗口 bounds `1536×1055`，`screencapture` 成功生成
1536×1055、RGBA PNG。产物：

```text
artifacts-os/os-window.png
sha256=4b17090c7f4883cefb986ad3f9cbe198b28a11959898f52d75d369d92069bac
```

截图可见 P01 窗口和 counter/button，范围是目标 OS window；它没有 scene ID、GPU
fence 或 backend present 通知，因此只能标为 best-effort，不能证明某个
`on_next_frame` 对应的 frame 已经 presented。

## Provider verdict

| provider / API | verdict | 结论 |
| --- | --- | --- |
| `render_to_image`（macOS，test-support） | `reject` | API 可编译，但当前锁定版本运行时返回 not implemented。 |
| a11y tree | `limited_adopt` / 语义树要求 `reject` | 可安全报告 inactive/null；未激活时没有树，不能作为完整语义 provider。 |
| `on_next_frame` | `limited_adopt` | 可作为 scene/frame hook 和耗时观测；不能替代 presented-frame 通知。 |
| macOS `screencapture` window | `best_effort` | 能抓目标 OS window，但不绑定 GPUI scene/fence/present。 |

## 最小上游接口提案

P01 不建议在 gpui-cli 内伪造接口。若要满足 O-10/O-11，最小上游能力是：

1. macOS backend 提供真实 scene readback，明确是否等待 renderer fence，并返回
   scene/revision 标识；当前 `render_to_image` 的运行时错误必须保留为能力状态。
2. 提供独立的 presented-frame/commit 通知，或明确的 present fence；
   `on_next_frame` 继续只表示 frame hook。
3. 在 AccessKit 未激活时提供明确的“不可用”状态；若要无屏幕阅读器导出，需
   独立启用语义树并提供稳定 logical ID、role、bounds、clip 与分页语义。

## 当前状态

P01 进入 `in_review`，但不进入 `done`：scene readback、完整 a11y tree、
transport-under-block、窗口关闭/休眠/device-loss 和 presented-frame 证据仍未

`on_next_frame` 冒充为更强能力。
